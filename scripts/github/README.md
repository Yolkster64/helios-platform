# scripts/github: repository truth, applied from `main`

The scripts that reconcile `Yolkster64/helios-platform`'s live GitHub configuration with
what is checked in, plus the two hygiene passes. They are driven by
`.github/workflows/governance-apply.yml` (rulesets, settings, labels, milestones) and
`.github/workflows/branch-prune.yml` (branch prune); the duplicate-issue closer runs from an
owner login. Design and the one owner step (the `HELIOS_ADMIN_TOKEN` fine-grained PAT, with
the click path): `docs/architecture/CONNECTIONS_SETUP.md` § Control fabric.

## Shared contract

- **Dry run by default.** Without `-Apply` a script only GETs, diffs and prints; `-Apply` is
  the only thing that mutates.
- **GET-diff-then-print-then-apply, per item.** The exact `gh api` command is printed
  BEFORE it runs, so an interrupted pass still leaves the replay line; a failed item never
  aborts the pass, and the run ends with a consolidated replay list.
- **Exit codes**: `0` = success or clean dry run; `1` = an item failed (replay list printed)
  or the input is invalid; `2` = precondition or credential missing (`gh` not on PATH, the
  repository unreadable on the wire, or the required permission absent under `-Apply`).
- **Wire truth, never `gh auth status`**: the precondition is `gh api repos/{repo}`'s exit
  code plus one boolean `.permissions.*` field (`scripts/verify/rest-connect.ps1` doctrine).
- **`-Json`** emits exactly one object on stdout and nothing else (human lines suppressed or
  moved to stderr); the exit contract is unchanged.
- **Secrets**: no token value is ever read, stored or printed; `gh` reads `GH_TOKEN` by name
  or its keyring, and the scripts see only exit codes and JSON.
- **One wire layer, copied verbatim into each script** (`$script:GhApiArgs` +
  `Invoke-GhApi`): every `gh api` call carries `X-GitHub-Api-Version: 2022-11-28` (gh 2.63.2
  sends none by itself) and the printed replay lines show it; a 429, or a 403 whose message
  names the rate/secondary limit, sleeps `Retry-After` (60 s when absent) and retries ONCE;
  no other status is retried (a 4xx fails identically, a blind POST retry double-creates);
  mutations are paced >= 1 s apart (prune `-Apply` issues ~190 against the ~80/min
  secondary limit). Lists page explicitly with `per_page=100&page=N` because
  `gh api --paginate` follows `Link` to `repositories/<id>/…`, which the agent proxy 403s.
- **Existence reads are three-way**: only GitHub's own `"status":"404"` body means "absent"
  (plan the create); any other failed read is `unknown (HTTP n / reason)` - no mutation,
  informational in a dry run, a failed item under `-Apply` (a blind POST would 409).
- **Measured from agent containers** (2026-09-05): the proxy there returns
  `.permissions.admin` and `.permissions.push` as `false`, blocks `repos/{repo}/pages` and
  the `actions/secrets|variables` listings (HTTP 403, no `status` field in the body) and
  rejects `%23` in paths (HTTP 400 "could not be canonicalized"), so only the dry runs are
  possible; the apply path is the workflow on `main` or an owner workstation.
- **Attribution-footer caveat**: label and milestone descriptions written through the Claude
  container's proxy come back with a trailing `_Generated by [Claude Code](https://claude.ai/code)_`
  footer (measured on all 4 milestones). The manifests carry the plain text, so the
  workflow's first run on `main` reconciles them as ordinary description PATCHes; until then
  the milestone dry run reads `update=4`.

## How the workflows drive them

- **`governance-apply.yml`** — `plan` job on `pull_request` touching `.github/rulesets/**`,
  `config/github/**`, `scripts/github/**` or the workflow (`GITHUB_TOKEN`, `contents: read` +
  `pages: read`, all four scripts in dry run, diff table in the job summary); `apply` job
  on `push` to `main` (same paths), the daily `schedule` (06:17 UTC drift net) or
  `workflow_dispatch` (`apply` boolean, `scope`
  `all|rulesets|settings|labels|milestones`) with `GH_TOKEN` = `HELIOS_ADMIN_TOKEN` when
  stored, else `github.token`. Labels and milestones apply with either token; rulesets and
  settings apply only with the PAT and otherwise report "needs HELIOS_ADMIN_TOKEN". Exit 2
  rows are reported, never red; exit 1 fails the job. Every script is called with
  `-Repository $GITHUB_REPOSITORY` (a fork reconciles itself); every `pwsh` command line
  is echoed before it runs; concurrency group `governance-apply` (plan: `governance-plan-<PR>`),
  never cancelled mid-pass.
- **`branch-prune.yml`** — `workflow_dispatch` only (`apply` default false, `keep`,
  `max_delete` default 200), `permissions: contents: write` + `pull-requests: read`,
  `GITHUB_TOKEN`: prints the command, runs `prune-branches.ps1 -Repository
  $GITHUB_REPOSITORY -Json -MaxDelete <n>`, renders the table and the report's `nextStep`
  into the job summary, uploads the `branch-prune-report` artifact (90 days), then
  re-raises the script's exit code.

```powershell
pwsh scripts/github/apply-rulesets.ps1                 # dry run
pwsh scripts/github/apply-repo-settings.ps1            # dry run
pwsh scripts/github/apply-labels.ps1 -Json             # one object
pwsh scripts/github/apply-milestones.ps1
pwsh scripts/github/prune-branches.ps1 -Json > branch-prune-report.json
pwsh scripts/github/close-duplicate-issues.ps1         # classification table, changes nothing
gh workflow run governance-apply.yml -f apply=true -f scope=all   # the apply path, from main
gh workflow run branch-prune.yml                       # plan; then -f apply=true -f keep=<a,b> [-f max_delete=<n>]
```
